# Matriks RLS — Mutaba'ah Tahfidz STHQ

Status per migrasi `0008_data_induk_siswa` (Oktober 2026). Sumber kebenaran: `drizzle/migrations/` (salinan identik di `supabase/migrations/`).
Bukti otomatis: `supabase/tests/rls_test.sql`, dijalankan oleh `npm test` (`src/test/rls-sql.test.ts`, PGlite + tiruan auth Supabase).

## Ringkasan

- Semua 17 tabel di `public` memakai RLS. Semua policy ditujukan ke `authenticated`; tidak ada policy untuk `anon`.
- **anon**: tidak punya hak tabel, sequence, atau fungsi apa pun di `public`. Hak bawaan Supabase dicabut di 0003, termasuk default privileges untuk objek baru.
- **Multi-peran** (sejak 0006): satu akun boleh memegang beberapa peran di `user_roles`; hak dari setiap peran berlaku bersamaan, tidak lebih. `has_role()` hanya menjawab untuk `auth.uid()` sendiri. Admin mengatur peran lewat `atur_peran_user()`.
- **Wali** baru bisa membaca data anak setelah `profiles.persetujuan_data_pada` terisi (`consent_ready`), dan hanya untuk anak di `wali_santri`.
- **Badal** hanya berwenang pada halaqah di `penugasan_badal` selama `mulai ≤ hari ini (Asia/Jakarta) ≤ selesai`. Sehari setelah `selesai`, aksesnya hilang.
- **Pengawas** hanya membaca halaqah dengan `halaqah.pengawas_id = dirinya`, beserta santri dan catatannya; tidak bisa menulis.
- **Kepsek** membaca seluruh data sekolah; tidak bisa menulis apa pun.
- **TU** mengelola data induk santri dan relasi wali; tidak membaca setoran maupun kehadiran.
- **Bendahara**: belum punya akses data selain profil sendiri dan data referensi. Modul keuangan menyusul.
- **Konten agama** (`quran_ayat`, isi `hukum_tajwid`) wajib memakai `rujukan` berstatus `disetujui`. Ini ditegakkan trigger untuk semua pemanggil, termasuk pemilik database.

### Aturan `setoran` / `setoran_iqro`

| Aksi   | Ustadz / badal (halaqah sendiri)                                                                                          | Wali (anak sendiri, setelah persetujuan)                                                                                               |
| ------ | ------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Baca   | semua catatan santri di halaqahnya                                                                                        | semua catatan anaknya (sekolah dan rumah)                                                                                              |
| Insert | hanya `tempat='sekolah'`, `diisi_oleh` = dirinya, belum diparaf                                                           | hanya `tempat='rumah'`, `diisi_oleh` = dirinya, belum diparaf. Nilai opsional, sesuai form "Nilai (opsional)".                         |
| Update | hanya catatan `tempat='sekolah'`. Trigger `validate_entry` mengunci `santri_id`, `diisi_oleh`, `tempat`, dan kolom paraf. | hanya paraf pada catatan `tempat='sekolah'`: `diparaf_oleh` = dirinya, **sekali saja**. Kolom lain, termasuk `nilai`, ditolak trigger. |
| Delete | —                                                                                                                         | —                                                                                                                                      |

Pengawas dan kepsek hanya membaca. Admin bebas, kecuali validasi jalur (`tahfidz`/`iqro`) dan perhitungan `jumlah_baris` di trigger. Akun ustadz yang juga wali mengikuti kolom ustadz untuk santri halaqahnya dan kolom wali untuk anaknya di halaqah lain.

## Fungsi SECURITY DEFINER

Semua fungsi di bawah memakai `set search_path=public`, mereferensikan tabel dengan nama schema lengkap, dan tidak bisa dijalankan `anon`.

| Fungsi                                                                                                                                      | Cek peran                                                           | Catatan                                                                                      |
| ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `has_role(uuid, app_role)`                                                                                                                  | hanya menjawab bila `_user_id = auth.uid()`                         | Pengguna tidak bisa menanyakan peran orang lain.                                             |
| `consent_ready()`, `owns_child(uuid)`, `teaches_halaqah(uuid)`, `can_read_halaqah(uuid)`, `can_read_santri(uuid)`, `can_teach_santri(uuid)` | berbasis `auth.uid()`                                               | Predikat untuk policy; hanya mengungkap izin pemanggil sendiri. Kepsek ikut di `can_read_*`. |
| `atur_peran_user(uuid, app_role[])`                                                                                                         | wajib admin                                                         | Mengganti seluruh peran user; admin tidak bisa mencabut peran admin dirinya.                 |
| `set_user_role(uuid, app_role)`                                                                                                             | wajib admin                                                         | Versi lama satu peran; dipertahankan untuk kompatibilitas.                                   |
| `kontak_wali_santri()`                                                                                                                      | admin/TU/kepsek, pengampu (`can_teach_santri`), wali (`owns_child`) | Hanya kolom nama & nomor HP orang tua/wali/darurat; tanpa NIK, KK, alamat.                   |
| `kesehatan_santri()`                                                                                                                        | admin/TU/kepsek, wali (`owns_child`)                                | Hanya `catatan_kesehatan`. Wali kelas menyusul bersama rombel.                               |
| `create_profile()`                                                                                                                          | trigger                                                             | Hak eksekusi dicabut dari semua role API.                                                    |

Fungsi `validate_entry()`, `guard_santri_update()`, `validasi_rujukan()`, `wajib_rujukan_disetujui()`, `verse_range_summary()`, `hari_efektif()`, dan `hari_hadir_efektif()` berjalan sebagai SECURITY INVOKER, sehingga tunduk pada RLS pemanggil. `hari_hadir_efektif` mengembalikan NULL untuk santri yang tidak terlihat oleh pemanggil.

## Menjalankan uji

```sh
npm test                                                           # lokal, tanpa Docker/DB
psql "$DB_URL" -v ON_ERROR_STOP=1 -f supabase/tests/rls_test.sql   # terhadap database Supabase nyata (transaksi di-rollback)
```

Uji yang dijalankan `npm test` memutar semua migrasi di PGlite dan mencetak `LULUS: …` untuk setiap skenario. Skenario yang gagal berhenti dengan `GAGAL: …`.
